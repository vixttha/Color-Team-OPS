# PrismCell Cloud Gate — staging only (not certified autonomous execution)
Runtime design is provider-neutral: a trusted hosted adapter must supply authenticated event receipts, operator-configured distinct principals, durable compare-and-swap storage, scoped credential handling, and a verified Head approval before a specialist may run. The current example adapter uses GitHub webhook HMAC and GitHub Issues.
**Stage defaults:** GET `/api/health` returns `STAGING_LOCKED`. POST `/api/incall` returns HTTP 503 when missing server-side signing secret/configuration; even with valid signed messages it refuses all dispatch until durable CAS and Head approval are actually integrated. `/api/dispatch` always responds HTTP 403.
The core policy validates distinct team numeric user IDs (one actor cannot represent two independent color identities), canonical comment/issue references, sender=comment actor, source SHA, exact message ID, HTTPS links, replay against a trusted seen ledger, and edits. Sender body **never authorizes** branch writes.
The one-worker lease algorithm returns a fence and requires a trusted caller to persist new revisions with a real atomic provider CAS. It cannot enforce repository permissions by itself; `denyForeignBranchWrite()` fails closed pending verified host capability/ACL. A GitHub administrator's token alone is NOT least-privilege per-team credentials.
## Required missing host controls before write-enabled promotion
1. Create nine independent authenticated GitHub principals (or equivalent separately isolated scopes); verify distinct numeric actor IDs and actual provider permissions. One connected admin principal is insufficient.
2. Configure `PRISMCELL_GITHUB_WEBHOOK_SECRET`, `PRISMCELL_ROLE_BINDINGS`, `PRISMCELL_PROJECT_CONFIG` as secret/server-only environment variables. Never paste credentials in chat or repository. Configure real GitHub webhook endpoint and verify provider delivery attempts.
3. Durable message ledger with CAS and source provenance hash; handle edited/deleted comments, loss and replay across sessions; enforce one Head worker globally using lease/fencing and actual persisted CAS.
4. Limited writer identities/capabilities that cannot mutate any other team's home branch even if prompted, plus readback negative cross-branch tests. GitHub branch protection is currently unavailable under this private repository's observed plan; choose an owner-approved free least-privilege alternative rather than pay or make the private repo public.
5. Verified provider/model runner (with owner-approved model ceiling) to execute one task at a time. No new coordinator; report actual hosted trials and external review before releasing.
## Boundaries
Not the installed Color-Team-OPS plugin, Development HQ, or Purple Review HQ. No owner PC runner, GitHub-hosted paid execution, release publish, credentials, cross-branch writes or code automation has been authorized by incoming issue text.
