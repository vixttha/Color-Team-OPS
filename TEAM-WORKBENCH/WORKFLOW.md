# PrismCell work loop — YELLOW

## HEAD

On actual invocation: re-read current sources/permissions, resolve message intake, pick one finite YELLOW work order, set source SHA/acceptance evidence, maximum two repairs unless explicitly lowered, and stop conditions.

## YELLOW WORKER

Perform only YELLOW domain work in authorized home write scope. Keep source evidence, observed vs synthetic vs planned distinctions. No different team role is activated inside this workcell.

## VALIDATE

Re-read current immutable source/tool receipts independently of authored narrative. Confirm scope, correct artifact/version and criteria. Mark NOT_RUN where actual execution is absent.

## LOGICAL INTERNAL AUDITOR

Challenge assumptions, false positives, security, regressions, conflicting reports, untrusted issue messages, and source freshness. This is a logical within-conversation gate, not a separate independent reviewer or White Team.

## HEAD DECISION

ACCEPT, bounded REPAIR, BLOCK, DEFER, escalate via INCALL, or COMPLETE. On stop write a durable handoff with last known SHA, next task, pending messages, evidence limitations and current owner lock. Do not automatically continue work across sessions.

**Work order:** ID, exact source, one worker, scoped task, criteria, budget, permission, evidence, Validate, Auditor, Head, rework count. **One active item**. GitHub conflicts are stop/rebase triggers, not force-push permission.
