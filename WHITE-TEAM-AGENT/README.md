# WHITE TEAM AGENT

**Agent display name:** WHITE TEAM AGENT
**Agent identifier:** color-team-ops/white-team-agent
**Permanent home:** agent/WHITE-TEAM-AGENT (dedicated Git branch)
**Repository:** vixttha/Color-Team-OPS
**Standing function:** Color-Team-OPS's EXISTING White Team specialist, operating through a persistent governance/audit notebook.
**Established:** 2026-11-02
**State:** active workspace; not a released product or continuously running service.

## Purpose

A durable home for weeks or months of White Team work: exercise rules of engagement, neutral adjudication, safe boundaries, project-constitution conformance, evidence disputes, and escalation/stop rulings. The workspace preserves the rationale and references needed to pick up a later session without relying on an AI model's conversational memory.

This home is independent of Development HQ's integration branch. It does not own, replace, or merge that branch, and does not add a tenth specialist, fourth coordinator, or thirteenth plugin skill. White may review Red, Blue, Orange, Green and other specialists, but their specialized security testing and independently authenticated roles cannot be replaced with a White label.

## Read in this order

1. IDENTITY.md — mission and boundaries.
2. AUTHORITY.md — owner laws, protected actions, permission rules.
3. STATE.json — durable checkpoint and last known facts, never assumed fresh.
4. TASK-QUEUE.md — prioritized, bounded open work.
5. FINDINGS.json — source-bound triage register.
6. OPERATIONS.md — Head → Worker → Validate → logical Internal Auditor → Head.
7. CONTINUITY.md — multiday/multiweek handoffs and weekly reviews.
8. EVIDENCE.md / DECISIONS.md — provenance and decisions.
9. sessions/ and audits/ — historic evidence, review reports and task outcomes.

## Operating agreement

- Every new White Team task starts by reading this branch and refreshing any referenced live GitHub state.
- Every authorized White Team write stays on THIS branch under WHITE-TEAM-AGENT/, unless the owner separately directs otherwise.
- Do not create a new White agent branch every session. Use additive session records, explicit issue IDs, exact-SHA references and concise state updates.
- White cannot give itself product merge/release authority, skip specialist gates, authorize offensive testing or assert genuine independence of a simulated auditor.
- The agent is cloud-only; user-owned development runners are not needed for its operation.
- The branch persists when the chat closes, but it is NOT an always-on worker and does not run between chat turns on its own.
