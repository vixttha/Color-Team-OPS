## Safe migration sequence

1. Preserve v0.0.1 source and both adopter records, indexes, schemas, documentation, workflow controls and original Git SHAs as immutable comparison sources.
2. Finish v0.0.2 schema/extension contract: support `maxLength`, preserve `limitations`/`project_milestone`, define stable host-local overrides and never reinterpret idea/feature status as permission or release.
3. Create two adopter profiles: an empty standalone starter and a populated host instance. Run unchanged record fixtures plus invalid-type, malicious Markdown, symlink and stale-index negative tests for both.
4. Apply an explicitly proposed no-clobber **diff-based** upgrade to separate review branches of MONDEX and D-D-World only upon owner authorization. Do not recopy entire trees. Merge local hardening, not wipe local changes.
5. Verify exact resulting source SHAs and deterministic indexes on an isolated authorized disposable cloud host; no assumptions about user's local PC. Require a distinct reviewer and human owner acceptance. Mark external/real-adopter proof unknown until obtained.
6. Keep Governance independent: no upstream registry, dependency, YAML-to-JSON conversion, shared release status, or automatic synchronization.

**Verdict:** current adopter record catalogs show no dangling idea references and do not assert testing/shipping; the upgrade path is **BLOCKED** by MIG-01/02/03 until repaired. This is a compatibility review, not a claim that two host products are bug-free or production-accepted.
