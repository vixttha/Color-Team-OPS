## Findings — prioritized

### H1 — Persistent self-hosted runner code-execution boundary / protections not verified (HIGH RISK EXPOSURE, not confirmed compromise)

Source: `.github/workflows/v0.0.1-runner-ci.yml`; `docs/design/RUNNER-POLICY.md`.

The workflow automatically checks out and executes Python tests on **persistent owner-managed Windows/Linux runners for each push** to the release branch. It does not run untrusted PR events, its token is read-only, its exact SHA is checked and its checkout is pinned — positive mitigations. Nevertheless, if an unauthorized actor can push code to that branch, the workflow could run arbitrary repository code on the owner's machines. Repo branch-protection API returned **403 integration access denied**; rulesets API returned **403 indicating a private-repo plan restriction**. Actual write restrictions and required review gates are **NOT VERIFIED**, not asserted absent. GitHub explicitly cautions that persistent self-hosted runners do not offer clean ephemeral isolation.

**Action:** Confirm who can push to the release branch and applicable plan-based protections. Consider an owner-controlled manual approval gate or staging reviewed source before dispatch, locked runner groups, isolation and no privileged secrets. Preserve permission to use owner runners for development; never introduce a runtime dependency.

### M2 — Plugin identity tests hard-code a transient old-record state (MEDIUM: future cleanup blocker)

`tests/test_plugin_identity.py` currently *requires* the old plugin's `status=superseded_creator_record_present`, `creator_record_present=true` and old-draft `version=0.0.2`. These assertions will fail after the owner successfully deletes the old record and the registry is truthfully updated. This is a regression-test design defect rather than a failing current test.

**Action:** Replace snapshot-specific assertions with lifecycle-state acceptance (`present` and `verified_deleted` with required verification evidence). Ensure an old entry can transition to verified removal without fabricating success. Test both states independently. Never derive actual deletion from a local JSON registry.
