## One Head-controlled execution lane — dispatch contract

**Head preflight** sets owner authorization, repo/branch and pinned SHA, exact purpose, selected feature ledger, one writer branch, allowed tools/actions, cost/retry/handoff limits, checkable acceptance criteria and stop conditions. The ordinary loop, for **every** selected Worker assignment, is:

`HEAD(scope & one dispatch) → WORKER(execute, self-check, bounded repair, evidence) → VALIDATE(real tool and exact-SHA evidence) → INTERNAL AUDITOR(separate logical adversarial check) → HEAD(accept/reassign/repair/stop)`.

A team may **recommend** the next specialist but never self-dispatch, grant tools, waive evidence, override owner release/host authorization or claim independent human identity. No fixed order across all nine colors. Same team may return for another distinct task after a properly audited prior assignment **if consented budget permits**.

If a required tool/consent/cloud service does not exist, Head must issue `CAPABILITY_BLOCKED`/`UNVERIFIED` (or pending external release approval), not fabricate execution. Prompt-based role changes within ChatGPT are **logical** and cannot themselves create independently authenticated agents, background jobs or cross-session exclusive writing.
